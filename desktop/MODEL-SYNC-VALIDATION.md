# 模型同步与启动优化验收

日期：2026-09-22。Windows 本机开发版，使用真实 Electron、Pi RPC 和已安装的完整生态资源；接口回归使用本地模拟服务，没有调用付费模型。

## 行为

- 对话、图片、视频使用一个账户级模型目录，请求在所有会话间合并。
- 每次启动先显示缓存，后台读取 JarodFund `/models` 一次；运行期间不定时检查，切回窗口、切换会话或打开设置也不重复请求。需要更新时可以点击顶部模型旁的刷新按钮或设置中的“刷新对话模型”。首次连接或更换 Key 时使用验证账户返回的模型列表。
- 更新模型配置时保留已有的输入能力、推理配置等元数据；不猜测未知新模型的推理档位。
- 新增模型可以在原会话中选择。原生运行时只重读本地 JarodFund 模型配置，不重载所有扩展、不新建会话、不重启进程。
- 刷新列表不更改当前模型，也不打断运行中的任务。网络失败保留原列表，本次运行不自动重试；手动刷新可以立即重试。
- 模型缓存按 Key 指纹区分，不保存 Key。更换账户、退出或同一个 Key 重新验证后，较早的后台响应不会覆盖新状态。
- 已记住 Key、已退出或加密凭据不可读时，不再启动 PowerShell 读取无用的备用环境凭据。
- 桌面扩展可以复用 Pi 已加载的 SDK 对象；扩展工厂、工作区隔离和 `/reload` 语义继续保留。
- 窗口显示后先读取模型缓存和历史列表；助手初始化期间可以输入文字，初始化完成不会覆盖刚输入的内容。
- 底部状态明确显示“本地助手已就绪”，与设置里的服务商模型同步状态区分。

## 回归

- `model-catalog.test.cjs`：请求合并、缓存、媒体分流、元数据保留、超时/空列表不覆盖、成功或失败后隔天读取不再自动同步、重启再次同步、手动刷新重试、跨账户及同账户迟到响应、Windows 文件替换占用时仅重试本地写入。
- `startup-patches.test.cjs`：精确版本检查、幂等修补、与现有导航修补共存；真实 RPC 原地加载和切换新模型，进程与会话 ID 不变。
- `model-catalog-ui.cjs`：自动刷新、手动刷新、当前会话使用新模型、正在运行的任务不中断、已保存 Key 重开；模型请求仍在等待时界面已就绪；启动时输入不丢失。
- 现有导航、工作区隔离、重载、运行环境回归通过。完整安装资源检查仍为 18 个智能体、40 个活动工具及 Playwright 技能。
- 根目录 `npm run check` 与桌面 JavaScript 语法检查通过。

## 测速与边界

测量区分窗口创建、完整界面加载、RPC 就绪，不把窗口显示等同于可以调用全部工具。

| 场景 | 窗口 | 完整界面 | RPC 就绪 |
| --- | --- | --- | --- |
| 本轮首次完整资源启动，未启用 SDK 复用 | 0.88 秒 | 1.39 秒 | 40.85 秒 |
| 后续未启用 SDK 复用的启动 | 0.90 秒 | 1.50 秒 | 15.54 秒 |
| 后续启用 SDK 复用的启动 | 0.87 秒 | 1.55 秒 | 15.01 秒 |

首次导入总计约 27.8 秒；后续两次约 7.4 / 6.8 秒。首次与后续测量受磁盘及转换缓存影响，不能把 41 秒到 15 秒全部归因于代码优化。SDK 复用在这组对照中的改善有限，尚未实现完整扩展瞬开。对已记住 Key 的用户，另消除了原先最长等待 5 秒的多余环境凭据查询；该收益不包含在上表的虚拟环境 Key 测试中。

网络回归刻意保持 `/models` 请求未返回，验证它不再影响窗口和本地助手就绪。真实 JarodFund 网络耗时、渠道负载和新模型推理能力不在本次离线验收范围内。

2026-09-22 已将这些修复纳入 0.1.1 安装器和本轮服务器交付。九项基础技能展示过滤也已纳入；资源清单为 release 2，16 个资源 ZIP 的内容哈希保持不变。精确文件大小与验收边界见 RELEASE-VALIDATION.md，完整交付和分片的校验结果随产物保存。
